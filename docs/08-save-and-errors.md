# 08. 저장·오류 메시지 구현 지침

진행 상황을 **브라우저에 저장하는 방법**과, 상황별 **안내·오류 메시지**를 정합니다.

---

## 1. 저장 방식

- 브라우저 **localStorage**에 JSON 문자열로 저장한다.
- 저장 열쇠(key): `mulgyeol-fishing-save`
- 저장 시점: 상태가 바뀌는 함수가 끝날 때마다 `saveGame()` 호출(자동 저장). 저장 버튼은 따로 없다.
- 저장하지 않는 것: 지금 낚시 상태(IDLE, WAITING…), 미니게임 위치, 디버그 옵션.
  - 즉, 낚시 도중 새로고침하면 **그 낚시는 없던 일**이 되고 IDLE로 시작한다(이미 소모한 미끼는 돌아오지 않음).

---

## 2. 저장 데이터 구조 (version 1)

```js
{
  version: 1,
  gold: 100,
  currentRegion: 'lake',
  unlockedRegions: ['lake'],
  ownedRods: ['bamboo'],
  equippedRod: 'bamboo',
  baits: { worm: 0, shiny: 0, golden: 0 },
  selectedBait: 'basic',
  bagCapacity: 20,
  bag: [],                         // docs/05 1-1의 객체 배열
  collection: {},                  // docs/06 1장
  claimedRegionRewards: [],        // 보상 받은 지역 id
  kingAchieved: false,             // 낚시왕 축하 모달을 봤는지
  stats: { totalCaught: 0, totalCasts: 0, totalEarned: 0 }
}
```

- 새 게임은 `docs/04` 1장의 시작 값으로 위 구조를 만든다(`createNewState()` 함수).

---

## 3. 불러오기 순서 (게임 시작 시 한 번)

```
1. localStorage를 쓸 수 있는지 확인 (try/catch로 테스트 값 쓰고 지워보기)
   └ 못 씀 → 새 게임으로 시작 + E09 배너. 이후 saveGame()은 아무것도 하지 않음.
2. 저장 열쇠로 값 읽기
   └ 없음 → 새 게임으로 시작 (메시지 없음)
3. JSON.parse
   └ 실패 → E10 처리
4. 검사: version이 1이고, 2장의 열쇠가 모두 있고, 타입이 맞는지
   └ 실패 → E10 처리
5. 통과 → 그 값으로 게임 시작
```

**E10 처리**: 기존 값을 `mulgyeol-fishing-save-broken` 열쇠로 옮겨 보관하고, 새 게임으로 시작한 뒤 E10 모달을 한 번 띄운다.

**검사 항목 (4번)**
- `gold`, `bagCapacity`: 0 이상의 정수
- `currentRegion`: `unlockedRegions` 안에 있는 값
- `equippedRod`: `ownedRods` 안에 있는 값
- `bag`, `unlockedRegions`, `ownedRods`, `claimedRegionRewards`: 배열
- `collection`, `baits`, `stats`: 객체
- 알 수 없는 물고기·지역·낚싯대 id가 있으면 그 항목만 버리고 계속 진행한다(전체를 망가진 것으로 보지 않음).

---

## 4. 데이터 초기화

- 설정 모달(⚙️) → `데이터 초기화` → 확인 모달 → `초기화`.
- 저장 열쇠를 지우고 새 게임 상태로 바꾼 뒤 화면 전체를 다시 그리고 낚시 탭으로 간다.
- 토스트 `🔄 처음부터 다시 시작해요`.

---

## 5. 메시지 목록

메시지는 `js/data.js`의 `MESSAGES` 객체에 코드별로 모아 두고, `{변수}` 부분을 바꿔 끼워 쓴다.

| 코드 | 상황 | 메시지 | 표시 방법 |
|---|---|---|---|
| E01 | 가방이 가득 찬 상태에서 던지기 | `가방이 가득 찼어요. 가방에서 물고기를 팔아 자리를 만들어 주세요.` | 토스트 |
| E02 | 골드가 부족한데 구매·해금 | `골드가 부족해요. (필요 {price}G / 보유 {gold}G)` | 토스트 |
| E03 | 선택한 미끼가 0개인데 던지기 | `{baitName}가 다 떨어져서 기본 미끼로 바꿨어요.` | 토스트 |
| E04 | 도감 조건이 부족한 지역 해금 | `도감을 {required}종 이상 채워야 {regionName}에 갈 수 있어요. (현재 {count}종)` | 토스트 |
| E05 | 기다리는 중에 너무 일찍 당김 | `너무 일찍 당겼어요! 물고기가 놀라서 도망갔어요.` | 토스트 |
| E06 | 입질 후 1초 안에 못 당김 | `아쉬워요, 입질을 놓쳤어요.` | 토스트 |
| E07 | 미니게임 진행도 0% | `물고기가 도망갔어요…` | 실패 모달 |
| E08 | 미니게임 25초 초과 | `줄이 끊어졌어요! 너무 오래 버텼어요.` | 실패 모달 |
| E09 | localStorage를 쓸 수 없음 | `이 브라우저에서는 저장이 안 돼요. 창을 닫으면 기록이 사라져요.` | 상단 배너 (닫기 버튼 없음, 계속 표시) |
| E10 | 저장 데이터가 망가짐 | `저장된 기록을 읽을 수 없어서 새로 시작해요.` | 모달 (확인 버튼) |
| E11 | 저장 중 오류 (용량 초과 등) | `저장하지 못했어요. 잠시 후 다시 시도할게요.` | 토스트 (같은 오류는 1분에 한 번만 표시) |

- E03의 조사: 미끼 이름이 모두 `미끼`로 끝나므로 `가`로 고정한다.
- E04의 `{regionName}에`는 그대로 쓴다("에"는 받침과 상관없이 자연스럽다 → "심해 협곡에").

### 안내(오류가 아닌) 메시지 모음
| 상황 | 메시지 |
|---|---|
| 퍼펙트 캐스팅 | `✨ 퍼펙트 캐스팅!` |
| 한 마리 판매 | `🪙 {fishName}을(를) {price}G에 팔았어요` |
| 모두 판매 | `🪙 {count}마리를 {total}G에 팔았어요` |
| 구매 | `✅ {itemName} 구매 완료!` |
| 낚싯대 구매(자동 장착) | `✅ {rodName} 구매 완료! 바로 장착했어요.` |
| 장착 | `🎣 {rodName}을(를) 장착했어요.` |
| 가방 확장 | `✅ 가방이 {capacity}마리로 커졌어요!` |
| 미끼 최대 | `미끼는 최대 999개까지 가질 수 있어요.` |
| 지역 해금 | `🔓 {regionName}이(가) 열렸어요!` |
| 지역 이동 | `🗺️ {regionName}(으)로 이동했어요` |
| 지역 도감 완성 | `🎉 {regionName} 도감 완성! 보상 {reward}G를 받았어요` |
| 미발견 도감 카드 | `아직 발견하지 못한 물고기예요.` |
| 초기화 | `🔄 처음부터 다시 시작해요` |

- `을(를)`, `이(가)`, `(으)로`처럼 괄호 조사를 그대로 쓴다(받침 계산 기능은 만들지 않는다).

## 6. 완료 기준·검증 기준

- [ ] 물고기를 낚고 새로고침하면 골드·가방·도감이 그대로다.
- [ ] 개발자 도구 → Application → Local Storage에 `mulgyeol-fishing-save`가 보이고 2장 구조와 같다.
- [ ] 개발자 도구에서 저장 값을 `{망가짐`으로 바꾸고 새로고침하면 E10 모달이 뜨고 새 게임이 시작되며, `mulgyeol-fishing-save-broken`에 원래 값이 남아 있다.
- [ ] 시크릿 창 등에서 localStorage가 막혀도 게임이 멈추지 않고 E09 배너가 뜬다(테스트: `localStorage.setItem`을 일부러 오류 내도록 바꿔서 확인 후 원래대로).
- [ ] 데이터 초기화 후 골드 100G, 호수, 대나무 낚싯대, 빈 가방·도감으로 돌아간다.
- [ ] 5장 표의 모든 메시지가 해당 상황에서 표의 문구 그대로 나온다.
